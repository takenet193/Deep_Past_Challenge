# Deep Past Challenge - データセット概要と前処理ガイド

## 1. コアデータ

### 1.1 `train.csv`

- **内容**: 約 1,500 件の旧アッシリア語テキスト（転写）と英訳のペア（文書レベル）。
- **カラム**:
  - `oare_id`: OARE データベースの ID（テキストを一意に識別）。
  - `transliteration`: 楔形文字タブレットの **アッカド語転写テキスト**。
  - `translation`: 対応する **英訳テキスト**。

### 1.2 `test.csv`

- **内容**: テスト用の **文単位**転写。スコアリング時には本番テストセットに差し替えられる。
- **特徴**: 学習データ（`train.csv`）は文書レベルだが、テストは **文レベル**で評価される。
- **カラム**:
  - `id`: 各文を一意に識別する ID（提出ファイルと対応）。
  - `text_id`: 文書 ID（同じテキストに属する文をグループ化）。
  - `line_start`, `line_end`: タブレット上での行番号の範囲（`1`, `1'`, `1''` など文字列型）。
  - `transliteration`: アッカド語転写テキスト（この文に対応）。

### 1.3 `sample_submission.csv`

- **内容**: 提出ファイルのテンプレート。
- **カラム**:
  - `id`: `test.csv.id` と一致。
  - `translation`: 予測した英訳（モデル出力）を記入する列。

## 2. 追加データ（教師データ拡張候補）

### 2.1 `published_texts.csv`

- 約 8,000 テキストの転写＋詳細なメタデータ（OARE / CDLI / ラベル / ジャンルなど）。
- **翻訳は付かない**が、どの出版・博物館・カタログに対応するかを追える。
- カラム例:
  - `oare_id`, `online transcript`, `cdli_id`, `aliases`, `label`, `genre_label`, ほか。

### 2.2 `publications.csv` & `bibliography.csv`

- **`publications.csv`**: 約 880 本の論文・書籍本文を OCR＋LLM でテキスト化したもの。
  - `pdf_name`, `page`, `page_text`, `has_akkadian` など。
  - 中に複数言語（英・仏・独・トルコ語…）の翻訳が混在。
- **`bibliography.csv`**: 上記に対応する書誌情報（タイトル・著者・ジャーナル・年など）。

> 公式ワークフローでは、これらから **翻訳部分を抽出 → 英語に統一 → 文単位アラインメント** を行い、追加学習データを構築することが推奨されている。

### 2.3 辞書・レキシコン系

- **`OA_Lexicon_eBL.csv`**
  - 旧アッシリア語の語彙リスト。
  - カラム例: `type`（語種）、`form`（転写表記）、`norm`（正規化形）、`lexeme`（辞書形）、`eBL`（オンライン辞書 URL）など。
  - 固有名詞や語形正規化の手掛かりとして利用可能。
- **`eBL_Dictionary.csv`**
  - eBL のアッカド語辞書本体。`OA_Lexicon_eBL` の URL が指す中身を一括で持つファイル。

### 2.4 その他の補助ファイル

- **`resources.csv`**: 追加で使えそうなリソース一覧。
- **`Sentences_Oare_FirstWord_LinNum.csv`**:
  - `train.csv` の文書内で「各文の最初の語と行番号」を記録した補助ファイル。
  - `train` を **文単位に分割し、`test` に近い粒度へ整列**する際のガイドになる。

## 3. 転写テキストのフォーマットと前処理（要点）

### 3.1 転写テキストの特徴

- 音節ごとにハイフン区切り（例: `ma-nu-ba-lúm-a-šur`）。
- 上付き・下付き数字や特殊文字（語形や書記の違いを表す）。
- 大文字の使い分け:
  - 先頭のみ大文字: **人名・地名などの固有名詞**。
  - 全部大文字: **シュメール語ロゴグラム**（例: `KÙ.BABBAR`）。
- **決定詞（determinatives）**: `{d}`, `{ki}`, `{m}` などが `{}` で囲まれ、名詞の種類（神名・地名・人名など）を示す。
- 欠損部分や破損箇所が多数存在し、`[x]`, `…`, `[...]` などで表現される。

### 3.2 現代書記記号（Modern Scribal Notations）

転写・翻訳に現れる、学術編集上の注記:

- 行番号（`1`, `1'`, `1''` など）。
- `!`（確実な読解）, `?`（不確実な読解）, `/`（行の継ぎ目）, `:` や `.`（語区切り）。
- `()`（コメント、欠損・抹消に関する説明）。
- `< >`（挿入）、`<< >>`（誤字マーク）、`[ ]`（明らかな欠損）、`˹ ˺`（部分欠損）。

### 3.3 公式が推奨する前処理

**削除（除去）推奨の記号**:

- `!`（確実な読解）
- `?`（不確実な読解）
- `/`（行区切り）
- `:` または `.`（語区切り）
- `< >` の「括弧自体」（中身の文字列は保持）
- `˹ ˺`（部分欠損）
- `[ ]`（文書全体の転写では括弧だけ除去し、中身を残す: 例 `[KÙ.BABBAR] → KÙ.BABBAR`）

**置換（正規化）推奨のパターン**:

- 欠損・ブレイク:
  - `[x]` → `<gap>`（1 文字程度の欠損）
  - `…`、`[… …]` → `<big_gap>`（複数文字〜大きな欠損）
- 上付き数字・決定詞:
  - `ki {ki}` などはガイドに従った統一表記へ（例: 上付き数字付きの `il₅` など）。
  - `Ḫ ḫ` → `H h` など、テストセットに合わせた単純置換が推奨されているケースもある。

### 3.4 決定詞 `{...}` の役割

- `{d}`: 神名
- `{mul}`: 星・天体
- `{ki}`: 地名・地理
- `{lu₂}`: 人・職業
- `{e₂}`: 建物・施設（宮殿・神殿など）
- `{uru}`: 集落・都市名
- `{kur}`: 土地・領域・山
- `{mi}`, `{m}`: 女性名 / 男性名
- `{geš}`, `{tug₂}`, `{dub}`, `{id₂}`, `{u₂}` など: 素材・物品・植物 等

本データセットでは、**`{}` は決定詞にのみ使われる**ため、前処理でも「決定詞マーカー」として扱いやすい。

## 4. 公式が想定する追加データ構築フロー（要約）

1. **転写と翻訳の対応付け**:
   - `published_texts.csv` の ID / 別名 / 博物館番号を使い、`publications.csv` 内の該当テキストと翻訳を結びつける。
2. **翻訳を英語に統一**:
   - 翻訳が英・仏・独・トルコ語など混在しているため、機械翻訳などで英語に統一する。
3. **文単位アラインメント**:
   - 転写と翻訳を文単位に分割し、1 対 1 のペアに揃える。
   - これが機械翻訳モデルの学習・評価に最も使いやすい形式になる。

このフローを完了すると、`train.csv` に加えて **大規模な文レベルの追加学習データ**を得ることができる。
